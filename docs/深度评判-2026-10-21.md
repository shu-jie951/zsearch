## 三、六维度评判

### 3.1 代码质量 — 8.8

**做得好的**

- 分层清晰：`config`（配置）→ `sources/*`（各上游适配）→ `aggregator`（合并去重排序）→ `server`（HTTP/渲染）→ `public/*`（界面）。没有出现「路由里写业务、业务里写 DOM」的混乱。
- 注释解释**决策原因**，这在真实项目里比解释代码本身值钱。例如 `runOne` 里那段：

  > 硬超时只是"我们选择不等了"，不代表源坏了……若在这里记一笔失败，两阶段搜索的第一阶段每次都砍在 6 秒，连续三次就能把唯一可用的 pansou 送进 10 分钟冷却，整个站瞬间"什么都搜不到"。

  这条注释挡住的是一个会让站点整体瘫痪的改动，任何人改到这里都会先停一下。
- 一致性：CSS 只消费变量不写死色值；JS 用同一套 `step/ok` 断言风格；错误一律「安全枚举」不透传上游原文。

**短板**

- `server.js` 已到 **46611 字节**，路由、`/go` 解析、安全页渲染、日志都在一个文件里。功能上没问题，但继续加会变难维护。
- 部分魔法数仍散在代码里（如 `MAX_H = 220` 与 CSS `max-height:220px` 两处需手工同步，已在注释里互相指认）。

### 3.3 性能 — 8.5

**已解决的六个来源**（前一轮「画面切换非常卡」）：

1. `will-change` 常驻 → 改为切换期间才挂（两张全屏层常驻约 10MB 且不回收）
2. 两个 `linear-gradient` 之间做 `transition` → 渐变不可插值，白付一次重绘
3. 壁纸层没做 `contain` → 加 `contain: paint`
4. 切换中玻璃层 `backdrop-filter` 未降级 → 淡入途中摘掉
5. 噪点层在切换时仍参与合成 → 临时 `opacity: 0`
6. filter 链里多余的 `blur()` → 移除

**本轮新增的两处「把等待变成毫秒」**：

- 云盘筛选：全量缓存还在就本地过滤 → **20s / 0 条 → 3ms / 24 条**
- 垃圾输入：归一化后直接短路 → **20015ms → 1~3ms**

**剩下的瓶颈在上游，不在本站。** pansou 单次 8~20s，这不是优化代码能解决的。
能做的只有「先给一部分」和「命中缓存」，两者都已做。

### 3.4 健壮性 — 8.7

- 每个源独立超时，谁挂不拖累别人。
- 源健康熔断：连续失败进冷却，冷却期 0ms 跳过。
- `slow-empty` 启发式：跑满 6s 还 0 条 → 判「疑似挂了」而不是「真没结果」。
- **不缩水合并**：第二阶段条数少于第一阶段时只做并集，避免用户眼看结果消失。
- 硬超时**不记健康失败**（关键设计，见 3.1 引用）。

**本轮修掉的一个真实语义缺陷**：失败原因在 `aggregator → server → 前端` 链路上被丢掉了，
导致「上游超时」和「确实没有」显示同一句话。现在三层贯通，超时时给「重试一次」，
真没结果才引导换词。`_qa_empty.js` 18 项断言锁死这个行为。

**做不到的**：上游整体不可用时，除了如实说「没等到」，没有别的办法。不塞假数据是刻意选择——
假数据会让用户点进「资源不可用」，比空手更伤信任。

### 3.5 安全 — 9.0

- `/api/search` **绝不下发 `raw_url`**，只给本站 `/go/<hash>` 短链，白名单校验留在服务端。
- 白名单只收叶子域名，`baidu.com` / `uc.cn` 这类顶级域**不收**（否则等于把开放重定向开在自家门口）。
- 仿冒识别：品牌名内嵌、编辑距离、后缀异常打分；兄弟后缀（`123pan.com` / `.cn`）豁免。
- 严格响应头：CSP、`nosniff`、`frame-ancestors`、`permissions-policy`；风险页内联脚本转义。
- 输入归一化摘标签：`<script>alert(1)</script>` → `alert(1)`（实测）。

**边界（写在 README 和免责页里）**：浏览器做不了真病毒扫描。本项目的「防病毒」= 跳转前拦截 + 域名信誉 + 危险文件类型标注。含 `.exe` 双扩展名等会标高风险。

### 3.6 设计与一致性 — 9.0

- 令牌集中在 `base.css` 的 `:root`，亮暗双主题；**一处极窄暖橙** `#E16C28`，其余全低饱和中性灰。
- 纸感调性：纸底 `#FBFAF9` / 墨色 `#16161A`，logo 三处同源（`logo.svg` / `favicon` / 页面内联）。
- 本轮搜索框放大：高度 108 → 约 178px，字号 16 → 18px，按钮 30 → 34px；移动端字号保 17px。
- 智能交互三件套全部有 `prefers-reduced-motion` 降级；柔光用 `pointerType === 'touch'` 直接跳过触屏。

**一致性上修掉的一处**：结果页原来没有清空按钮（首页有）。同一个动作在两页表现不一致，是最容易被感知到的半成品感——已补上并支持 Esc。

## 五、本轮发现并修掉的三个真实缺陷

这三个都是**实测暴露**的，不是读代码猜的。

### 缺陷 1：垃圾输入让上游白等 20 秒

**现象**：`q=` 传 80 个 `a`，接口耗时 **20015ms** 后返回 0 条。
**原因**：没有输入归一化，任何字符串都直接打到上游。
**修法**：`normalizeQuery()` —— 摘标签、去控制字符、压空白、截断 80 字符；识别「无 CJK 且无空格且超长」的 ASCII 垃圾串直接短路。
**结果**：**20015ms → 1~3ms**，`source: 'invalid'` + 友好提示。

### 缺陷 2：云盘筛选比不筛还慢，而且结果是空的

**现象**：全量搜「甄嬛传」8.1s 出 60 条（含大量夸克）；点「夸克」筛选 → **20s 后 0 条**。
**原因**：筛选重新问上游，pansou 的 `cloud_types` 过滤反而更慢，直接超时。
**修法**：全量缓存还在时，就地过滤（`localFilter` 计数可观测）。
**结果**：**20s / 0 条 → 3ms / 24 条**，且与全量里夸克数完全一致（`两次条数一致: true`）。

### 缺陷 3：上游超时被说成「没有找到相关资源」

**现象**：pansou 卡 20 秒被硬超时后，用户看到「没有找到相关资源」。
**原因**：`aggregator` 给了 `timedOut/error`，但 `server.js` 的 providers 映射只留 `{id,count,ms,ok}`，原因在链路上丢了。
**修法**：三层贯通 —— 聚合层带 `timedOut`；接口层输出**安全枚举** `error`（`timeout/cooling/no-data/error`）并据此判 `reason: 'upstream-timeout'`；前端超时态给专门文案 + 「重试一次」按钮，真没结果才引导换词。
**结果**：`_qa_empty.js` **18/18**，且验证了「点重试确实会重发请求」——按钮不是摆设。

## 八、结论

这个项目**可以交付**。

它不是「功能堆了一堆但一半点不动」的那种：14 轮实测、445+ 条断言、零控制台报错，
